# 3D-Store — контекст проекта

Магазин моделей, напечатанных на 3D-принтере. Владелец добавляет модели с
ценой и вариантами филамента, клиенты заказывают с оплатой при получении и
общаются с владельцем в чате по каждому заказу.

Интерфейс и общение с пользователем — **на русском языке**.

## Стек и архитектура

- Node.js + Express, без фронтенд-сборки (обычные HTML/CSS/JS в `public/`).
- База: libSQL/SQLite через `@libsql/client` — **асинхронный** клиент.
  - локально и на VPS — файл `store.db` в каталоге `DATA_DIR`
  - в облаке — Turso (`DATABASE_URL` + `DATABASE_AUTH_TOKEN`)
- Медиа моделей хранится **в базе** (таблица `images`), отдаётся через
  `GET /img/:id`. На диск ничего не пишется — так работает на хостингах
  с временной файловой системой.
  - фото приводятся к WebP (sharp): поворот по EXIF, ужатие до 1600px;
    анимированные GIF конвертируются со всеми кадрами
  - короткие видео (mp4/mov, ролик Live Photo) хранятся как есть, без
    перекодирования; обложкой товара всегда становится первое **фото**
  - галерея — до 10 файлов, порядок в `product_images.pos`
- Пароли (владельца и клиентов) хэшируются bcrypt. Сессии — httpOnly-куки:
  `owner_session` для владельца, `user_session` для клиентов.

## Файлы

```
src/server.js   — Express, всё API; async-обработчики обёрнуты в wrap()
src/db.js       — подключение к libSQL, схема (init() при старте)
src/tg.js       — низкоуровневый Telegram Bot API (sendMessage/sendPhoto/…)
src/bot.js      — бот: магазин для клиентов + команды владельца (long polling)
src/notify.js   — уведомления владельцу и клиентам в Telegram
public/         — index.html (витрина), admin.html (кабинет), order.html
                  (мои заказы + чат), js/{store,admin,order,auth}.js
deploy/         — установка на VPS (CentOS/RHEL 9): setup-centos.sh,
                  update.sh, systemd-юнит, конфиг nginx
```

## Роли и доступ

- **Владелец** — вход по паролю на `/admin`. Первый пароль берётся из
  `OWNER_PASSWORD` (по умолчанию `admin`), меняется в кабинете.
  Забытый пароль сбрасывается переменной `RESET_OWNER_PASSWORD`.
- **Клиенты** — аккаунты «юзернейм + пароль», **без email**. Регистрация
  обязательна для оформления заказа. Клиентам из Telegram аккаунт создаётся
  автоматически (`users.telegram_chat_id`).

## Telegram-бот

Один бот на всех (`src/bot.js`, long polling — вебхук и публичный URL не нужны).
Владелец определяется сравнением chat id с `TELEGRAM_CHAT_ID`; всё остальное —
клиенты. Диалог оформления заказа — конечный автомат, состояние в таблице
`tg_state` (`qty → name → phone → address → confirm`).

Команды владельца: `/menu`, `/orders`, `/setpass <новый>` — смена пароля
админки **без старого пароля** (доверенный канал = чат владельца), при этом
сбрасываются все сессии в `sessions`.

Проверять права нужно по chat id на каждом действии: смена статуса и
`/setpass` доступны только владельцу.

## Темы оформления

Дизайн в эстетике Linear: **тёмная тема основная**, шрифт Inter, индиговый
акцент `#5e6ad2`, волосяные границы `rgba(255,255,255,.08)`, мелкие радиусы
(8–16px), радиальное свечение за заголовком, приглушённый серый текст.

Обе темы — переменные в `:root` (тёмная) и `:root[data-theme="light"]`.
`public/js/theme.js` подключается в `<head>` **до** отрисовки — иначе будет
вспышка; он переключает тёмную ↔ светлую, хранит выбор в localStorage и
правит `<meta name="theme-color">`.

Новые цвета добавлять только через переменные — иначе тёмная тема отвалится.

## Скиллы дизайна

В `.claude/skills/` лежат скиллы из проекта **taste-skill** (MIT). Главный —
`redesign-skill`: чек-лист «generic AI»-паттернов (чистый #000, три равные
колонки, одинаковый радиус, отсутствие фокус-колец, `window.alert()`,
пустые alt и т.п.). Перед правками дизайна стоит прогнать по нему аудит.

## Цены, скидки и подарки

Порядок расчёта везде один: **акционная цена → доплата за вариант →
персональная скидка → подарок за сумму**. Считается только на сервере
(`server.js` и `bot.js`) — значениям с клиента не доверяем.

- **Акция на модель**: `products.sale_price`. Если она задана и меньше
  `price`, витрина и бот показывают старую цену зачёркнутой.
  `effectivePrice()` выбирает действующую цену, `parseSalePrice()`
  отбрасывает мусор (0, отрицательные, больше базовой).
- **Персональная скидка** (`discounts`): «купил модель A
  (`trigger_product_id`) → скидка `percent`% на модель B
  (`target_product_id`)». Действует, если у клиента есть **неотменённый**
  заказ с моделью-триггером (`discountFor()`). Процент пишется в
  `orders.discount_percent`.
- **Подарок за сумму** (`gifts`): «заказ от `min_total` ₽ — модель
  `product_id` в подарок». `giftForTotal()` берёт **самый крупный
  подходящий** порог; название и id пишутся в `orders.gift_name` /
  `orders.gift_product_id`, чтобы владелец не забыл положить подарок.
  На один порог — одно правило (повторный POST перезаписывает модель).
  `GET /api/gifts` публичный: витрина показывает, сколько не хватает до
  подарка. Правила чистятся при удалении модели.

Карточка на витрине разворачивается на всю ширину сетки по кнопке
«Рассмотреть подробнее» (она же настоящая `<button>` — работает с
клавиатуры); клик мышью по карточке мимо фото и кнопки заказа делает
то же самое.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATA_DIR` | каталог файла базы (на VPS — `/var/lib/3d-store`) |
| `DATABASE_URL` / `DATABASE_AUTH_TOKEN` | облачная база Turso (вместо файла) |
| `OWNER_PASSWORD` | стартовый пароль владельца |
| `RESET_OWNER_PASSWORD` | аварийный сброс пароля при старте |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | уведомления о заказах |
| `PORT` | порт (по умолчанию 3000) |

Секреты в репозиторий не коммитим. На VPS они лежат в `/etc/3d-store.env`.

## Запуск и проверка

```bash
npm install
npm start            # http://localhost:3000, админка /admin
```

Автотестов нет. Проверка — вручную curl-ом по сценарию:
вход владельца → создание модели → регистрация клиента → заказ →
сообщения в чате с обеих сторон → смена статуса заказа.

## Развёртывание

- **VPS (основной вариант)**: `bash deploy/setup-centos.sh` от root.
  Ставит Node, systemd-сервис `3d-store`, nginx, открывает порты
  в firewalld и включает SELinux-флаг `httpd_can_network_connect`.
  Обновление: `bash /opt/3d-store/deploy/update.sh`.
  Логи: `journalctl -u 3d-store -f`.
- **Render + Turso** — бесплатный вариант, конфиг в `render.yaml`.
- Ветка `main` — рабочая, с неё идёт автодеплой на Render.

## Важные детали, которые легко сломать

- Загрузка фото — до 8 МБ (multer). В nginx обязателен
  `client_max_body_size` больше этого значения, иначе аплоад падает.
- Все обращения к базе асинхронные (`await db.get/all/run`) — синхронный
  стиль `better-sqlite3` больше не используется.
- Уведомления в Telegram шлются «фоново» (`.catch(() => {})`) и не должны
  блокировать оформление заказа, даже если Telegram недоступен.
