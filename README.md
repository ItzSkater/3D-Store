# 3D-Store 🧊

Сайт для продажи моделей, напечатанных на 3D-принтере.

- **Витрина** с каталогом: фото, цена и варианты филамента.
- **Кабинет владельца**: добавление/редактирование/удаление моделей, загрузка
  фото, варианты филамента с доплатой, управление заказами.
- **Аккаунты клиентов** — юзернейм + пароль (без email).
- **Оплата при получении** — онлайн-оплата не нужна.
- **Чат** по каждому заказу между владельцем и клиентом.
- **Уведомления в Telegram** о новых заказах и сообщениях.
- Данные (база и фото) хранятся в **облачной базе**, поэтому сайт работает
  даже на бесплатных хостингах и ничего не теряет при перезапусках.

## Технологии

- Node.js + Express
- База: **libSQL / SQLite** через `@libsql/client`
  - локально — файл `data/store.db`
  - в облаке — [Turso](https://turso.tech) (бесплатно, без карты)
- Фото хранятся **в базе** (не на диске сервера)
- Пароли хэшируются (bcrypt)
- Фронтенд — обычные HTML/CSS/JS, без сборки

## Быстрый запуск локально

```bash
npm install
npm start
```

Сайт: `http://localhost:3000`, админка: `http://localhost:3000/admin`.
Пароль владельца по умолчанию — `admin` (смените в кабинете).

## 🚀 Бесплатный деплой: Turso + Render

Полностью бесплатно, без карты, управляется через сайт (можно с телефона).

### Шаг 1. Облачная база Turso (2 минуты, без карты)

1. Зайдите на [turso.tech](https://turso.tech) → **Sign up** через GitHub.
2. В панели [app.turso.tech](https://app.turso.tech) → **Create Database**
   (любое имя, регион — ближайший).
3. Откройте созданную базу → скопируйте её адрес вида
   `libsql://имя-логин.turso.io` — это **DATABASE_URL**.
4. Там же **Create Token** (или «Generate token») → скопируйте токен —
   это **DATABASE_AUTH_TOKEN**.

### Шаг 2. Хостинг Render (бесплатный план)

1. Зайдите на [render.com](https://render.com) → войдите через GitHub.
2. **New → Blueprint** → выберите этот репозиторий (Render прочитает
   `render.yaml`).
3. Перед созданием задайте переменные-секреты:
   - `DATABASE_URL` — адрес базы из Turso (шаг 1.3)
   - `DATABASE_AUTH_TOKEN` — токен базы (шаг 1.4)
   - `TELEGRAM_BOT_TOKEN` — токен бота от `@BotFather`
     (`TELEGRAM_CHAT_ID` уже прописан в `render.yaml`)
4. Нажмите **Apply / Create** и дождитесь сборки.
5. Откройте выданный адрес — сайт готов. Админка: `/адрес/admin`.

> Важно: пароль владельца по умолчанию `admin` — сразу зайдите в админку и
> смените его (кнопка «Сменить пароль»).

### Где взять GitHub-репозиторий с кодом

Код лежит в ветке `claude/3d-models-ecommerce-site-kyhmyt`. При деплое на
Render/Railway в настройках сервиса можно выбрать эту ветку, либо слить её в
`main` через Pull Request на GitHub.

## 🖥 Свой VPS (CentOS Stream 9 / RHEL / Rocky / Alma 9)

Лучший вариант, если VPS уже есть: сайт не «засыпает», база лежит локально
(Turso не нужен), скорость выше.

Подключитесь к серверу по SSH и выполните **от root**:

```bash
curl -fsSL https://raw.githubusercontent.com/ItzSkater/3D-Store/main/deploy/setup-centos.sh -o setup.sh
bash setup.sh
```

Скрипт сам настроит всё: Node.js, код, зависимости, автозапуск (systemd), nginx,
firewalld и SELinux. В конце покажет адрес сайта и сгенерированный пароль
владельца.

### Что дальше

| Действие | Команда |
|---|---|
| Логи | `journalctl -u 3d-store -f` |
| Перезапуск | `systemctl restart 3d-store` |
| Настройки (пароль, Telegram) | `/etc/3d-store.env` |
| Обновить код с GitHub | `bash /opt/3d-store/deploy/update.sh` |
| База и данные | `/var/lib/3d-store/store.db` |

### HTTPS и домен

Подойдёт любой домен, в том числе бесплатный **DuckDNS**. Сначала убедитесь,
что домен указывает на IP сервера (в панели DuckDNS — поле «current ip»),
затем одной командой:

```bash
bash /opt/3d-store/deploy/setup-https.sh ваш-домен.duckdns.org
```

Скрипт проверит домен, установит certbot, пропишет домен в nginx, получит
бесплатный сертификат Let's Encrypt, включит перенаправление HTTP → HTTPS и
автопродление.

Вторым аргументом можно указать почту для напоминаний об истечении:

```bash
bash /opt/3d-store/deploy/setup-https.sh ваш-домен.duckdns.org почта@example.com
```

Проверить сертификаты: `certbot certificates`

### Резервная копия

```bash
cp /var/lib/3d-store/store.db ~/backup-$(date +%F).db
```

## 🚂 Альтернатива: Railway

Тоже деплой из GitHub через сайт. В проекте есть `railway.json`.

1. [railway.app](https://railway.app) → войти через GitHub →
   **New Project → Deploy from GitHub repo** → выбрать репозиторий.
2. Во вкладке **Variables** задать те же переменные:
   `DATABASE_URL`, `DATABASE_AUTH_TOKEN`, `TELEGRAM_BOT_TOKEN`,
   `TELEGRAM_CHAT_ID=8763963310`.
   (Можно и без Turso — тогда Railway хранит файл базы на своём **Volume**:
   создайте том с mount path `/data` и задайте `DATA_DIR=/data`.)
3. **Settings → Networking → Generate Domain** — получите адрес сайта.

Railway даёт стартовый кредит; постоянная работа — примерно от 5 $/мес.

## Telegram-бот 🤖

Один бот работает и как магазин для клиентов, и как панель владельца.
Владельца бот узнаёт по `TELEGRAM_CHAT_ID`, все остальные — клиенты.
Работает через long polling: публичный адрес сайта не нужен.

### Клиентам

- `/start` → меню: **🛍 Каталог** и **📦 Мои заказы**
- Каталог с фото, ценой и вариантами филамента, выбор кнопками
- Пошаговое оформление: количество → имя → телефон → адрес → подтверждение
- Оплата при получении
- Чат с продавцом прямо в боте; сообщения попадают в тот же чат заказа,
  что и на сайте
- Уведомления об ответах продавца и смене статуса заказа

Аккаунт клиенту создаётся автоматически при первом заказе — заказы видны
и в боте, и на сайте.

### Владельцу

| Команда | Действие |
|---|---|
| `/menu` | панель владельца |
| `/orders` | последние заказы, карточка заказа, чат |
| `/setpass новый_пароль` | **сменить пароль админки без ввода старого** |

Смена пароля из бота безопасна: команду принимает только чат владельца
(`TELEGRAM_CHAT_ID`). После смены все активные входы в админку сбрасываются.

Из карточки заказа владелец меняет статус кнопками (Подтверждён, Отправлен,
Выполнен, Отменён) и отвечает клиенту — ответ приходит клиенту в Telegram.

## Уведомления в Telegram 🔔

Владелец получает сообщение о каждом новом заказе и о новых сообщениях в чате.

Настройка — в кабинете владельца → кнопка «🔔 Уведомления», либо через
переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

Как получить:
1. `@BotFather` → `/newbot` → имя → скопировать **токен**.
2. Написать своему боту любое сообщение.
3. `@userinfobot` пришлёт ваш **Chat ID**.

## Забыли пароль владельца

Сброс через переменную окружения (лезть в базу не нужно):

1. На хостинге (Render → **Environment**, или Railway → **Variables**) добавьте
   переменную `RESET_OWNER_PASSWORD` со значением — новым паролем.
2. Сохраните — сервис перезапустится и перезапишет пароль на новый.
3. Войдите в `/admin` с новым паролем.
4. **Удалите переменную `RESET_OWNER_PASSWORD`** — иначе пароль будет
   сбрасываться при каждом перезапуске.

## Как это работает

### Владелец
1. Входит в `/admin` по паролю.
2. Вкладка **«Модели»**: добавляет товары (название, описание, цена, фото,
   варианты филамента с доплатой к базовой цене).
3. Вкладка **«Заказы»**: видит заказы, меняет статус (Новый → Подтверждён →
   Отправлен → Выполнен) и общается с клиентом в чате.

### Клиент
1. Регистрируется (юзернейм + пароль) или входит.
2. Выбирает модель, вариант, количество — оформляет заказ (оплата при получении).
3. В разделе **«Мои заказы»** следит за статусом и переписывается с продавцом.

## Структура проекта

```
src/
  server.js     — Express-сервер и API
  db.js         — подключение к libSQL/Turso и схема
  notify.js     — уведомления в Telegram
public/
  index.html    — витрина
  admin.html    — кабинет владельца
  order.html    — «Мои заказы» + чат клиента
  css/style.css — стили
  js/           — клиентские скрипты (store, admin, order, auth)

```

| `DATABASE_AUTH_TOKEN` | токен базы Turso | — |
| `OWNER_PASSWORD` | стартовый пароль владельца | `admin` |
| `TELEGRAM_BOT_TOKEN` | токен Telegram-бота | — |
| `TELEGRAM_CHAT_ID` | ваш chat id в Telegram | — |
| `PORT` | порт сервера | `3000` |
