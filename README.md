# 3D-Store 🧊

Небольшой сайт для продажи моделей, напечатанных на 3D-принтере.

- **Витрина** с каталогом моделей: фото, цена и варианты филамента.
- **Кабинет владельца**: добавление/редактирование/удаление моделей, загрузка фото, настройка вариантов филамента и цен, управление заказами.
- **Аккаунты клиентов** — юзернейм + пароль (без email). Для оформления заказа нужно войти.
- **Оплата при получении** (наложенный платёж) — онлайн-оплата не требуется.
- **Чат** по каждому заказу между владельцем и клиентом.
- **Уведомления в Telegram** о новых заказах и сообщениях.
- Готов к деплою на **Fly.io** (Docker + постоянный том).

## Технологии

- Node.js + Express
- SQLite (better-sqlite3) — данные хранятся в файле `data/store.db`
- Загрузка изображений — multer (папка `uploads/`)
- Пароли хэшируются (bcrypt)
- Фронтенд — обычные HTML/CSS/JS, без сборки

## Запуск

```bash
npm install
npm start
```

Сайт откроется на `http://localhost:3000`.

Порт можно задать через переменную окружения `PORT`.

### Первый вход владельца

Откройте `http://localhost:3000/admin`.

Пароль владельца по умолчанию — `admin`. **Сразу смените его** кнопкой
«Сменить пароль» в кабинете.

Задать другой начальный пароль можно при первом запуске:

```bash
OWNER_PASSWORD='ваш_пароль' npm start
```

(Пароль сохраняется в базе при первом старте; далее меняется только в кабинете.)

## Уведомления в Telegram 🔔

Владелец получает мгновенное сообщение в Telegram о каждом новом заказе и
о новых сообщениях клиента в чате.

Настройка (в кабинете владельца → кнопка «🔔 Уведомления»):

1. В Telegram напишите `@BotFather` → `/newbot` → задайте имя. Скопируйте
   **токен** вида `123456789:AA...`.
2. Напишите своему боту любое сообщение.
3. Узнайте свой **Chat ID** через бота `@userinfobot` (пришлёт число).
4. Вставьте токен и Chat ID в админке, нажмите «Проверить», затем «Сохранить».

Настройки хранятся в базе (в томе Fly), их не нужно прописывать в коде.
Как альтернатива — можно задать переменные окружения `TELEGRAM_BOT_TOKEN`
и `TELEGRAM_CHAT_ID`.

## Деплой на Fly.io 🚀

В проекте уже есть `Dockerfile` и `fly.toml`.

Один раз установите [flyctl](https://fly.io/docs/hctl/install/) и войдите:

```bash
fly auth login
```

Затем из папки проекта:

```bash
# 1. Создать приложение (подставит уникальное имя в fly.toml).
#    На вопрос про деплой сейчас — ответьте No, сначала создадим том.
fly launch --no-deploy

# 2. Создать постоянный том для базы и фото (в том же регионе, что в fly.toml).
fly volumes create data --size 1 --region waw

# 3. (необязательно) Задать стартовый пароль владельца как секрет.
fly secrets set OWNER_PASSWORD='ваш-надёжный-пароль'

# 4. Задеплоить.
fly deploy
```

После деплоя откройте сайт: `fly open`, админку — по адресу `/admin`.

Важно:
- **Том обязателен** — без него база и фото исчезнут при перезапуске.
- Токен Telegram задаётся прямо в админке (хранится в томе) — секреты
  для этого не нужны.
- Пароль владельца по умолчанию `admin` — смените его сразу после первого входа
  (или задайте через `fly secrets set OWNER_PASSWORD=...` **до** первого запуска).
- В `fly.toml` приложение работает на одной машине с примонтированным томом —
  это правильный режим для SQLite (том может использовать только одна машина).

## Как это работает

### Владелец
1. Входит в `/admin` по паролю.
2. Во вкладке **«Модели»** добавляет товары: название, описание, цена,
   фото и варианты филамента (у каждого варианта можно задать доплату к базовой цене).
3. Во вкладке **«Заказы»** видит все заказы, меняет их статус
   (Новый → Подтверждён → Отправлен → Выполнен) и общается с клиентом в чате.

### Клиент
1. Регистрируется (юзернейм + пароль) или входит.
2. Выбирает модель, вариант филамента и количество, оформляет заказ.
3. Оплата — при получении.
4. В разделе **«Мои заказы»** отслеживает статус и переписывается с продавцом.

## Структура проекта

```
src/
  server.js     — Express-сервер и API
  db.js         — схема и подключение SQLite
  notify.js     — уведомления в Telegram
Dockerfile      — образ для Fly.io
fly.toml        — конфигурация Fly.io
public/
  index.html    — витрина
  admin.html    — кабинет владельца
  order.html    — «Мои заказы» + чат клиента
  css/style.css — стили
  js/           — клиентские скрипты (store, admin, order, auth)
data/           — файл базы данных (создаётся автоматически)
uploads/        — загруженные фото моделей
```

## Данные и резервные копии

Всё хранится локально:
- база — `data/store.db`,
- фото — `uploads/`.

Для бэкапа достаточно скопировать эти папки. Они не попадают в git
(см. `.gitignore`).
